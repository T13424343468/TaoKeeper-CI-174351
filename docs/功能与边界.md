# 功能与边界（逐页说明）

> 口径：本文按真实源码与视图模型契约撰写，逐页写清**功能**、**数据来源**、**未测/未接线状态**。
> 全程道系铁律：未测/未扫/未知一律如实显示，不假数据、不空转；本层零写动作的页面绝不代做。
> 依据文件均为 `src/TaoKeeper.App/Views/*.xaml(.cs)` 与 `src/TaoKeeper.AppKernel/ViewModels/*.cs`，页末标注。
>
> **接线状态总述（截至文档发布时点）**：交付壳的页面注册表（`PageRegistry.cs`）已登记 11 条路由（总览、软件管家、磁盘清理、系统体检、性能加速、内存管理、驱动、弹窗、工具箱、挂件、设置；2026-11-12 P2 集成完成 XAML+VM 接线）；存储感知（Storage）按调度口径维持不占独立注册，未注册路由在壳内显示如实占位（「本页正在赶工」，无假数据）。下文各页所述「运行期接线」即指该集成环节与后续真机适配层接线。逻辑层测试基线见 `交付说明.md`。

## 1. 总览（HomePage）

- **功能**：远山 hero 图（水墨远山 + 朱砂落日，Path 手绘）、三格统计（体检评分 / 可清垃圾 / 可升级款数）、四快捷卡（软件管家、磁盘清理、内存管理、性能加速）、清理账最近三笔。
- **数据来源**：`HomePageViewModel` 聚合唯一事实源——体检评分取 `CheckupPageViewModel`、垃圾量取 `JunkScanResult`、软件可升级取 `SoftwarePageViewModel`、内存占用取监控引擎读数、清理账取 `CleanupLedger` 账本。本层只做转述与文案，不重算业务判定。
- **未测/未接线状态**：任何一项未扫描即如实显示（评分「未测」、垃圾「尚未扫描」、软件「尚未扫描软件清单」、内存「占用未知」）；hero 文案随状态切换（未测态「身体尚可，余尘未清」）。壳侧经 `MainWindow.HomeViewModelProvider` 注入数据，运行期接线前总览页按未测态兜底。
- 依据：`Views/HomePage.xaml(.cs)`、`ViewModels/HomePageViewModel.cs`、`MainWindow.xaml.cs`。

## 2. 软件管家（SoftwarePage）

- **功能**：页头三来源条（winget 官方源、GitHub Releases、官网直链）+ 四功能页签（软件库 / 升级中心 / 卸载中心 / 安全承诺）。升级按三分桶呈现：静默可跑（策略允许且哈希已校验）、需用户确认、策略拦截（哈希失配：硬规则，确认也不放行，界面标死不可执行）。
- **数据来源**：`SoftwarePageViewModel.BuildAsync` 经 Core 编排器 `SoftwareManagerCoordinator` 走 `ISoftwareSourceAdapter` 适配器；真实适配器为 `TaoKeeper.Adapters` 的 `WingetSoftwareSourceAdapter`（winget 命令行解析，`WingetOutputParser`）。静默升级默认关（道系口径），哈希失配必须拒绝，不受策略影响。
- **未测/未接线状态**：已装清单经 `InstalledListProvider` 钩子注入，未接线时如实显示「尚未扫描」；winget 缺失只影响本页通道，不假清单、不假「9,000+」等来源数字（三来源条文案为渠道说明，非实时数据）。
- 依据：`Views/SoftwarePage.xaml(.cs)`、`ViewModels/SoftwarePageViewModel.cs`、`Adapters/WingetSoftwareSourceAdapter.cs`、`Adapters/WingetOutputParser.cs`。

## 3. 磁盘清理（DiskCleanupPage）

- **功能**：环图卡（弧长=已勾选占可清合计的真实比例，未扫描不出弧）+ 可清项目卡（按清理规则聚合，体积降序）。默认勾选=低/中风险规则，高风险规则默认不勾、须手动勾选；勾选变化即时重算汇总；「清理（先进回收站）」按钮产出经确认闸门的清单。
- **数据来源**：`DiskCleanupPageViewModel.Build(JunkScanResult)` 接 Core 垃圾扫描结果，按规则聚合；磁盘容量概览为可选入参（真机接线后传入），未提供时如实写「磁盘容量待扫描后显示」。
- **未测/未接线状态**：未扫描显示「尚未扫描」，零候选显示「很干净，暂无可清」；**实际清理执行由 CleanupCoordinator 在用户确认后接线**，本页零写动作——按钮只产出经 `CleanupSafetyGate`（路径级预检，受保护路径标死）的确认清单。
- 依据：`Views/DiskCleanupPage.xaml(.cs)`、`ViewModels/DiskCleanupPageViewModel.cs`、`ViewModels/CleanupQueueViewModel.cs`。

## 4. 系统体检（CheckupPage）

- **功能**：环图卡（弧长=真实得分/100，未测不出弧）+ 发现卡（六维发现清单，按严重度降序）。「去处理」按发现项映射路由跳转（磁盘清理 / 工具箱 / 性能加速 / 存储感知 / 内存管理）。
- **数据来源**：`CheckupPageViewModel.RunCheckup(HealthContext)` 调 `HealthCheckEngine`，上下文由各模块扫描结果汇总填充。
- **未测/未接线状态**：上下文全空=未测态，界面显示「尚未体检」而非 100 分假象；缺项维度不误扣分。
- 依据：`Views/CheckupPage.xaml(.cs)`、`ViewModels/CheckupPageViewModel.cs`。

## 5. 性能加速（BoostPage，含启动项一节）

- **功能**：启动项建议卡（只列建议不代做：建议禁用=高风险、自行判断=中风险、内存瘦身建议）+ 进程占用排行卡。用户显式勾选提交后才执行，执行回执逐条转述（成功/未成）。
- **数据来源**：`SpeedupPageViewModel` 编排转述 `SpeedupCoordinator` 的计划与依据。适配层由外部装配——**默认内存台架（InMemoryStartupAdapter）仅测试用**，真机启动项/进程数据随运行期适配层接线。
- **未测/未接线状态**：未刷新时如实显示「尚未体检加速，暂无建议（等待运行期接线；不假数据）」。
- **启动项（子页/内嵌一节）**：原型 v19 中启动项为性能加速页内一节，不设独立导航路由。`StartupPageViewModel` 为只读清单（来源/风险/状态/命令行明细），只调适配器列清单、**不提供启用/禁用调用**；改系统的动作统一走性能加速页确认闸门。风险文案如实（未确认发布者不替用户下结论）。独立 `StartupPage` 文件保留自洽，由集成线按段内嵌复用其绑定。
- 依据：`Views/BoostPage.xaml(.cs)`、`ViewModels/SpeedupPageViewModel.cs`、`Views/StartupPage.xaml(.cs)`、`ViewModels/StartupPageViewModel.cs`。

## 6. 内存管理（MemPage）

- **功能**：物理/虚拟内存双仪表条、近一小时趋势（双折线，环形序列降采样）、进程占用排行（按工作集降序，默认 Top 15）、页面文件方案（五预设按钮）。
- **数据来源**：`MemPageViewModel.ApplySnapshot` 接 `MemoryMonitorEngine` 快照；页面文件预设建议与校验转述走 `PageFileSettingsValidator`。
- **未测/未接线状态**：无快照时占用率主显为空、不显示百分比。**本页零写动作**——页面文件改动需三步确认（确认→备份→应用），本层只展示方案与校验转述，应用属用户确认后的适配层动作（真机行为见首验清单第 4 条）。
- 依据：`Views/MemPage.xaml(.cs)`、`ViewModels/MemPageViewModel.cs`。

## 7. 驱动安装升级（DriverPage）【最小可用形态】

- **功能**：驱动清册表（设备/当前版本/可用版本/来源/动作，含已是最新行）。升级三道闸：备份（pnputil 导出）→ 逐项确认 → 执行；哈希失配标死不可执行（硬规则，确认也不放行）；高危设备（显卡/芯片组/存储/网络）必须逐项确认。新扫描后旧确认失效、逐项确认重来。
- **数据来源**：`DriverPageViewModel.LoadAsync` 经 Core 编排器 `DriverUpdateCoordinator` 走 `IDriverUpdateAdapter`；真实适配器为 `WindowsDriverUpdateAdapter`（WUA/官方渠道，`PnputilOutputParser` 解析 pnputil 输出）。只走官方渠道，不装第三方改版驱动。
- **未测/未接线状态**：未扫描时清册全空、如实显示「尚未扫描驱动清单」。
- **最小可用说明**：本页按最小可用形态交付——清册展示、状态判定（已是最新/需确认/可静默/标死）与确认闸门转述已完备；备份命令与回滚指引以文本转述交付，真机提权与备份执行路径以首验清单第 3、5 条为准。
- 依据：`Views/DriverPage.xaml(.cs)`、`ViewModels/DriverPageViewModel.cs`、`Adapters/WindowsDriverUpdateAdapter.cs`、`Adapters/PnputilOutputParser.cs`。

## 8. 弹窗管理（PopupPage）【最小可用形态】

- **功能**：规则清单（逐条开关）、白名单卡（命中即放行并留痕）、拦截记录卡（新→旧环形保留最近 50 条，可回溯），累计计数（拦截/放行/白名单放行）。
- **数据来源**：`PopupPageViewModel` 维护规则与白名单、做文本匹配判定与留痕转述；命中判定经 `PopupRule`/白名单优先级。
- **未测/未接线状态**：默认无规则（白名单为空、无记录，界面空态文案如实）。**合规红线：只做规则识别与提醒，不做窗口劫持、不改系统钩子**；实际关闭/放行动作永远由 Windows 适配层在用户确认策略下执行（随运行期接线，未接前本页仅维护规则与留痕）。
- **最小可用说明**：本页按最小可用形态交付——规则/白名单/记录的维护与判定契约已完备并有测试覆盖；真实窗口监听不在交付范围。
- 依据：`Views/PopupPage.xaml(.cs)`、`ViewModels/PopupPageViewModel.cs`。

## 9. 存储感知（StoragePage）

- **功能**：总开关卡（定时自动清理）+ 逐项勾选卡（四个清理范围：临时文件、回收站过期项、下载目录滞留件、浏览器缓存）+ 回收站语义注脚。间隔天数可设（最小 1 天）。
- **数据来源**：`StorageSensePageViewModel` 转述 `StorageSenseEngine` 的计划开关、到点判定（`EvaluateDue`）与预览产物。
- **未测/未接线状态**：**默认关，由用户打开**；开启后到点只产出确认预览（`PendingPreview`），绝不静默清理；实际清理等用户逐次确认后走回收站语义（适配层执行，`MarkRunCompleted` 记账）。清空最后一项范围需先关总开关（防呆）。
- 依据：`Views/StoragePage.xaml(.cs)`、`ViewModels/StorageSensePageViewModel.cs`。

## 10. 工具箱（ToolsPage，含磁盘空间分析、重复文件两个子页）

- **功能**：8 张快捷卡（4 列 × 2 行，顺序=原型）：大文件查找、重复文件、相似图片、右键菜单管理、文件粉碎、进程管理、磁盘空间分析、系统信息。**大文件查找、重复文件、磁盘空间分析**三卡点击展开结果区；其余五卡点击如实提示「随运行期接线启用」。
- **数据来源**：大文件与空文件夹清单经 `ToolboxPageViewModel` 转述 `ToolboxPlanner` 规划（空文件夹体积按 0 记），统一并入清理确认队列（逐条确认闸门，默认进回收站可还原）。
- **子页 · 磁盘空间分析（SpaceAnalysisPage）**：目录树式空间地图，只看不删。主路径接 `MftStreamingScanner` 的 MFT 流式扫描结果（目录按体积降序 Top-20、体积分层色 ≥1GB 朱砂 / ≥100MB 金 / 其余竹青、坏记录数/读取量/孤儿体积入汇总，孤儿不入清单）；**原生库不可用时便携降级**走目录遍历（`PortableDiskScanner`，无记录号/孤儿语义，如实标记便携模式）。父链重建失败退回裸名并如实标记，不编路径不假体积。
- **子页 · 重复文件（DuplicateFilesPage）**：三级漏斗识别、**零误报才报**——仅全文件 SHA-256 完全相同才判重复。每组保留一份（默认组内第一份，可改选组内单选）、其余默认列为待清理；「转入确认队列」经统一确认闸门（受保护路径/盘符根从源头标死）。空态如实「未发现重复文件」。
- **未测/未接线状态**：未扫描时结果区显示「尚未扫描」；相似图片、右键菜单管理、文件粉碎、进程管理、系统信息五卡当前**未落地**，点击只有如实提示，无任何功能承诺。
- 依据：`Views/ToolsPage.xaml(.cs)`、`Views/SpaceAnalysisPage.xaml(.cs)`、`Views/DuplicateFilesPage.xaml(.cs)`、`ViewModels/ToolboxPageViewModel.cs`、`ViewModels/SpaceAnalysisPageViewModel.cs`、`ViewModels/DuplicateFilesPageViewModel.cs`。

## 11. 桌面挂件（WidgetPage）

- **功能**：桌面挂件效果示意卡（120 环图：内存占用 + 垃圾概览 + 后台进程概览）+ 一键清理确认浮层入口。数据驱动：未就绪/过期整帧灰显，不出弧、不显示旧数；「清理（进回收站）」在确认浮层内为意图入口，须过明细确认浮层（逐项可勾、全部移入回收站、可还原）。
- **数据来源**：`WidgetPageViewModel.ApplyFrame` 接挂件一帧数据（`WidgetFrame`）；新鲜度窗口默认 90 秒，过期灰显而非展示旧数（`RefreshFreshness` 定时重判）。
- **未测/未接线状态**：无数据帧时初始即灰显；垃圾概览、后台进程任一项未就绪均如实说明。**真实桌面常驻挂件随运行期接线**，本页当前为示意卡与开关意图转述（开关只产出 `WidgetBootAction` 意图交适配层执行）；关闭挂件=移除自启+退出零残留（真机行为见首验清单第 6 条）。
- 依据：`Views/WidgetPage.xaml(.cs)`、`ViewModels/WidgetPageViewModel.cs`。

## 12. 设置（SettingsPage）

- **功能**：五组设置——界面主题（水墨/天青/墨白三选，全局即时生效）、通用（开机自启、开机后自动体检）、软件管家（默认安装位置、静默升级默认关、装完建快捷方式、记安装账）、清理与存储（存储感知默认关、快扫默认开）、桌面挂件（显示内容：内存/垃圾待清/磁盘余量；大小：标准/紧凑；内存告警线默认 85% 可调可关、磁盘余量提醒默认 10 GB 可调）。
- **数据来源**：`SettingsPageViewModel` 只读转述既有 `AppSettings` 模型；可写项走既有 `AppSettingsStore` 落盘契约（不新造存储文件格式）。
- **未测/未接线状态**：改动先进待确认副本（Pending），点「保存改动」经确认闸门后才写入设置文件；**未接存储渠道时保存仅本会话内存生效，按钮文案如实标明「仅本会话生效」**。非法输入（告警线越界、安装位置空值）防呆拒绝。**红线锁定项不可改**（模型层强制，任何写入路径不可绕过）：三层官方软件源、装前哈希校验、清理先进回收站。
- 依据：`Views/SettingsPage.xaml(.cs)`、`ViewModels/SettingsPageViewModel.cs`、`AppKernel/Settings/AppSettings.cs`、`AppKernel/Settings/AppSettingsStore.cs`。
